# Contributing

1. Keep skills generic and free of organization or customer identifiers.
2. Add one skill per `skills/<name>` directory.
3. Use lowercase hyphenated names that match the `name` field in `SKILL.md`.
4. Add only the tools and scripts the skill needs.
5. Run all validation commands from the README.
6. Submit changes through a pull request reviewed by CODEOWNERS.

Release tags are immutable. Publish a new version instead of moving an existing
tag.
